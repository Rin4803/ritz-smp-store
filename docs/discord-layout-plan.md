# แผนจัดโครงสร้าง Discord ของ RitzSMP

เอกสารนี้เป็น **แผนจัดหน้าตาและการใช้งาน Discord** สำหรับตรวจสอบกับผู้ดูแลก่อนปรับทรัพยากรจริง โดยตั้งใจคงเซิร์ฟเวอร์ ห้อง และบทบาทเดิมไว้ ไม่สร้างบอทตัวใหม่ ไม่ย้ายห้อง และไม่ใส่ token หรือค่าลับลงในเอกสาร

## เป้าหมาย

โครงสร้างควรทำให้สมาชิกแยกได้ทันทีว่าเรื่องใดเป็นการพูดคุยในเกม เรื่องใดเป็นคำสั่งของ RitzSMP AI เรื่องใดเป็นการฟังเพลง และเรื่องใดเกี่ยวกับร้านค้า/การเติมเงิน/รายงานผู้เล่น การจัดหมวดหมู่เป็นเพียงข้อเสนอเชิงภาพและสิทธิ์ ต้องตรวจชื่อห้องจริงกับผู้ดูแลก่อนกดแก้ไขบน Discord

## โครงสร้างที่เสนอ โดยคงห้องเดิม

| หมวดหมู่เชิงหน้าที่ | ห้องเดิมที่ควรอยู่ในกลุ่ม | ผู้รับผิดชอบหลัก | หลักการใช้งาน |
|---|---|---|---|
| ประกาศและช่วยเหลือ | ห้องประกาศ, ห้องสนับสนุน | AI bot/แอดมิน | ใช้ข้อความปักหมุดและ Embed ที่สั้น อ่านง่าย และมีลิงก์ร้านค้าเฉพาะเมื่อจำเป็น |
| ร้านค้าและการเงิน | ห้องโดเนท/ร้านค้า, ห้อง log การเติมเงิน/คำสั่งซื้อ | เว็บสโตร์/แอดมิน | แยกข้อความที่สมาชิกเห็นจาก log ภายใน ห้ามโพสต์ข้อมูลลับหรือเลขบัญชีเต็ม |
| เชื่อมบัญชีและสมาชิก | ห้องระบบเชื่อมบัญชี, ห้องรายชื่อสมาชิก | AI bot | ใช้ปุ่มและเมนูแบบ ephemeral เมื่อเป็นข้อมูลส่วนบุคคล และประกาศเฉพาะผลลัพธ์ที่ปลอดภัย |
| แชทจากเกม | ห้อง `server-chat` เดิม | DiscordSRV | ให้ข้อความจาก Minecraft แสดงชื่อและ prefix ตาม mapping เดิม ห้ามให้เว็บสโตร์ส่งข้อความซ้ำกับ DiscordSRV |
| สถานะเซิร์ฟเวอร์ | ห้อง `server-realtime` เดิม | Presence monitor/AI bot | แสดง online/offline, จำนวนผู้เล่น และเวลาตรวจล่าสุด ไม่ควรส่งข้อความใหม่ทุก polling รอบ ให้แก้ Embed เดิมหรือใช้ cooldown |
| เพลง | ห้องคำสั่งเพลงและห้องเสียงเดิม | Music bot | ใช้ `/play`, `/queue`, `/skip`, `/stop`, `/leave`; การมีสถานะบอทเข้าห้องไม่ถือว่าเสียงใช้งานได้จนกว่าจะมีผู้ฟังยืนยัน |
| รายงานผู้เล่น | ห้องรายงานผู้เล่นเดิม | Report interaction/แอดมิน | ให้ผู้ใช้ส่งผ่านเมนูและ modal, ส่ง Embed ไปห้องรายงาน, จำกัดการแก้ไขตามกติกา และไม่เปิดเผยรายละเอียดแก่คนที่ไม่เกี่ยวข้อง |

## มาตรฐานสีและข้อความ Embed

ใช้สีตามหน้าที่แทนการใช้สีสุ่ม ได้แก่ สีแดงสำหรับเหตุผิดปกติหรือคำเตือน, สีเขียวสำหรับการดำเนินการสำเร็จ, สีทองสำหรับร้านค้า/การสนับสนุน, สีม่วงสำหรับคำสั่ง AI และสีน้ำเงินสำหรับสถานะเซิร์ฟเวอร์ ทั้งหมดควรมีหัวข้อภาษาไทย บรรทัดสรุปหนึ่งบรรทัด และส่วนรายละเอียดที่อ่านได้จากมือถือ

ข้อความจากบอททุกตัวควรใช้ภาษาไทยเป็นหลัก ถ้าต้องแสดงคำสั่งหรือชื่อไฟล์ให้ครอบด้วย inline code และไม่แสดง token, signature, รหัสยืนยัน, RCON response เต็ม, URL ที่มี query ลับ หรือข้อมูลส่วนตัวของสมาชิกคนอื่น

## สิทธิ์ขั้นต่ำที่ควรตรวจ

AI bot ต้องส่งข้อความและใช้คำสั่งในห้องที่กำหนดเท่านั้น Music bot ต้องเห็นห้องคำสั่งและเชื่อมต่อ/พูดในห้องเสียงเท่าที่จำเป็น DiscordSRV ต้องส่งและอ่านข้อความใน `server-chat` รวมถึงใช้ webhook/สมาชิกตามที่ plugin ต้องการ ส่วนระบบรายงานต้องส่ง Embed ไปห้องรายงานและตอบ interaction ได้ แต่ไม่ควรมีสิทธิ์จัดการสมาชิกหรืออ่านทุกห้องโดยไม่จำเป็น

## ลำดับการปรับจริง

1. บันทึกภาพและชื่อห้อง/บทบาทปัจจุบันก่อนแก้ไข
2. ตรวจ channel mapping ใน DiscordSRV ให้ตรงกับห้อง `server-chat` และ `server-realtime` เดิม
3. ตรวจว่า AI bot และ Music bot ใช้ application/token แยกกัน และลงทะเบียนคำสั่งใน guild เดียวกันโดยไม่ซ้ำ
4. ทดสอบในห้องที่จำกัดสิทธิ์ก่อน ได้แก่ `/status`, ปุ่มเชื่อมบัญชี, `/queue` และข้อความ Minecraft หนึ่งบรรทัด
5. ตรวจผลบนมือถือและ desktop ว่าชื่อ/prefix ไม่ถูกตัดจนอ่านไม่รู้เรื่อง
6. ถ้าผลผ่านจึงค่อยปรับชื่อหัวข้อ สี Embed หรือข้อความปักหมุดทีละรายการ พร้อมเก็บภาพก่อน/หลัง

## เกณฑ์ยอมรับ

แผนนี้ถือว่านำไปใช้ได้เมื่อสมาชิกเห็นห้องเดิมในหน้าที่ที่ชัดเจน, ข้อความจาก Minecraft ไม่ซ้ำ, สถานะเซิร์ฟเวอร์ไม่สร้าง spam, คำสั่ง AI และ Music แยกบทบาทกัน, Embed ร้านค้าและรายงานไปห้องถูกต้อง และไม่มี secret หรือข้อมูลส่วนตัวปรากฏในข้อความ/บันทึกการตรวจ

> สถานะเอกสาร: จัดทำเป็นแผนแล้ว แต่ยังไม่ถือว่าเป็นการเปลี่ยนโครงสร้าง Discord จริงจนกว่าจะมีการตรวจสิทธิ์และกดยืนยันบน Discord production
