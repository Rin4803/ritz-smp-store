# วงจรชีวิตห้องเคส Player Report

## ขอบเขต

เอกสารนี้กำหนดพฤติกรรมของบอท RitzSMP AI สำหรับรายงานผู้เล่นใหม่ เพื่อแยกห้องสนทนาแต่ละเคสออกจากช่องหรือหมวดหมู่เดิมที่ผู้ดูแลสร้างเอง บอทใช้เฉพาะหมวดหมู่ที่มีชื่อ `💢┃player-report-log-บันทึกรายงานผู้เล่น` เป็นพื้นที่เก็บห้องเคสชั่วคราว

| เหตุการณ์ | พฤติกรรมที่บอททำ | ขอบเขตความปลอดภัย |
|---|---|---|
| ผู้เล่นส่งรายงาน | สร้างหรือใช้หมวดหมู่ที่บอทดูแล แล้วสร้างห้อง `report-<เลขเคส>` ภายในหมวดนั้น | เก็บ `caseChannelId` และ `caseCategoryId` ไว้กับรายงาน เพื่อลดความเสี่ยงในการอ้างถึงห้องผิด |
| สร้าง Embed | แสดงผู้รายงาน ผู้ถูกรายงาน ชื่อในเกม หมวดหมู่ รายละเอียด และเวลาส่ง | เวลาอ่านง่ายเป็น ICT (UTC+7) และมี Discord timestamp เพื่อแสดงเวลาตามอุปกรณ์และตรวจสอบย้อนหลัง |
| Staff ปิดเคส | บันทึกสถานะปิดในฐานข้อมูลก่อน แล้วจึงลบเฉพาะห้อง `report-…` ของเคสนั้น | หากบันทึกสถานะไม่สำเร็จ จะไม่สั่งลบห้องเคส |
| หลังลบห้องเคส | ตรวจหาห้องที่ยังอยู่ใต้หมวดเดียวกัน | ลบหมวดได้ต่อเมื่อไม่มีห้องย่อยเหลือ และชื่อ/รหัสหมวดตรงกับที่บอทบันทึกไว้เท่านั้น |
| เคสเก่าหรือห้องเดิม | ลบห้องเคสที่ระบุได้หลังปิดเคส แต่ไม่ลบหมวดหมู่ที่ไม่ได้บันทึกว่าเป็นของบอท | ป้องกันการลบช่องหรือหมวดหมู่ที่มีอยู่ก่อนระบบนี้ |

## ผลการตรวจโค้ด

การทดสอบถดถอยยืนยันการสร้างหมวดหมู่ด้วยชื่อที่กำหนด การส่ง Embed ที่มีเวลา ICT และ Discord timestamp การลบห้องเคสภายหลังบันทึกสถานะสำเร็จ และการคงหมวดหมู่ไว้เมือยังมีห้องเคสอื่นอยู่ ชุดทดสอบเต็มและ production build ผ่าน ณ รอบการปรับนี้ อย่างไรก็ตาม การทดสอบกดปิดเคสกับห้อง Discord จริงยังคงเป็นรายการค้างและต้องทำกับเคสทดสอบใหม่เท่านั้น
